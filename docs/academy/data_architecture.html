Data architecture: Vonnegut exports to bronze, silver, gold and the browser

Three Python scripts, run one after another on the analyst's computer, build three layers of the data in the private Supabase Storage bucket fix-data. Each script downloads the layer before it and uploads its own. The chat page downloads only the last layer, gold/, into a database inside the browser tab.

What each step does

  1. bronze.py reads each Excel file in Trading_FIX_Messages/ and replaces every real CompID in it with its fictitious CompID from CompID_Key.xlsx. It then searches the whole file for any real CompID; if one is found, it stops and uploads nothing. Otherwise it uploads the file to bronze/ with the same folder and file name. The real CompIDs never leave the analyst's computer.
  2. silver.py downloads the 36 files from bronze/, cleans the column names and types, and combines all rows of one FIX message type from all three months into one table. It uploads 11 Parquet files (a compressed file format for tables) to silver/. See Silver layer.
  3. gold.py downloads the 11 silver tables, merges the repeated rows into one row per message, fills missing CompIDs, links requests to their orders, and builds the 9 star schema tables. It uploads them to gold/. See Gold star schema.
  4. When the analyst enters the Supabase publishable key in the chat page, web/data.js downloads gold/manifest.json and the 9 Parquet files, creates the 9 tables in DuckDB-WASM (the version of the DuckDB database that runs inside a web page), and switches off the database's access to files, the network and its own settings.

Each script deletes from its own folder in the bucket any file it did not write in that run, so a folder holds only the output of the last run. silver.py and gold.py write their Parquet files to a temporary folder that is deleted when the script ends; no layer is kept in the repository folder, which is stored on Google Drive.

Rules for changing the data

  • Every CompID outside the analyst's computer is fictitious. The mapping file CompID_Key.xlsx is excluded from git and is never uploaded.
  • A change to the data is made by changing a script in code/ and running it and the scripts after it, so the change is written to Supabase. The repository holds no message data.
  • When new Excel exports arrive, they are added to Trading_FIX_Messages/ in a month folder and the three scripts are run in order: bronze.py, silver.py, gold.py.
