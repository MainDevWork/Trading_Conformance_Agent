Trading Conformance Agent: system architecture

An analyst types a question about the Vonnegut FIX message exports into a web page. A language model on OpenRouter writes SQL queries, agent.js runs them in the browser against the July–September 2026 data, which data.js downloads from Supabase, and the model writes the answer from the query results.

Answering one question

  1. 1app.js passes the whole conversation so far to chat() in agent.js. The project has no server: everything runs in the analyst's browser.
  2. 2agent.js sends OpenRouter the analyst's OpenRouter key, the system prompt (conformance background, table names) followed by web/knowledge/core.md, the conversation, and the definitions of five tools: list_tables, describe_table, run_sql, read_reference (one topic file from web/knowledge/, such as the test steps or session times) and lookup_reject_codes (reject code meanings from web/knowledge/reject_codes.json).
  3. 3The model returns either a tool call, for example run_sql with a SQL query it has written, or the final answer text.
  4. 4agent.js runs the tool call against the DuckDB-WASM tables. run_sql places the model's SQL inside SELECT * FROM ( … ) with a row limit.
  5. 5The result is returned to agent.js: at most 200 rows, cut to 30,000 characters. It is added to the conversation and step 2 runs again.
  6. 6When the model returns answer text, the page shows it, and under it each tool call with its SQL and result, so the analyst can check every number.

Loading the data and settings

  1. Adata_store.py reads each Excel file with python-calamine, renames columns to lower case with underscores, converts timestamps, prices and quantities, and saves a Parquet copy. This takes several minutes the first time and is skipped for files that have not changed.
  2. Bbuild_site_data.py combines the copies into one table per FIX message type, all three months together, and writes each table to data/ as a Parquet file, with manifest.json. Each Excel file is assigned to a table by the value in its Message Type column, not by its file name.
  3. Cupload_to_supabase.py uploads the files in data/ to the private bucket fix-data, using the Supabase secret key.
  4. DWhen the analyst enters the Supabase publishable key, data.js downloads manifest.json and the 11 Parquet files, creates the tables and the all_messages view, then switches off file, network and settings access for the database.
  5. Econfig.py reads code/.env: DATA_DIR, the Excel folder used in steps A and B, and SUPABASE_URL, SUPABASE_SERVICE_KEY and SUPABASE_BUCKET, used in step C. The OpenRouter key and model are entered in the page's sidebar.
