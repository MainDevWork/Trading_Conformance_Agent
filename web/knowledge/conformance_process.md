# The conformance test process (Volume 201 and 202)

- Conformance testing is mandatory before a client's software connects to the JSE production market, after any change to conformed software, and when a JSE release requires it.
- Testing happens in the JSE Customer Test Service (CTS) environment. The client first sends the Conformance Test Report (Volume 202) stating which functions its software supports; once the JSE agrees the scope, the client books a slot.
- Slots are on Tuesdays, Wednesdays and Thursdays that are JSE business days, at most one per week. All self-conformance tests must be completed within one JSE business day. Tests that need a JSE Customer Test Analyst (CTA) run between 07:00 and 19:00 SAST, on the same or the next business day.
- The client must stay connected and logged in throughout and must not disconnect or log off between steps unless the step says so. Any deviation from the test steps fails the test. Inaccurate information in the report fails the test. A client who fails must redo the full conformance test. Results are released 24 to 48 hours after the CTA runs the end-of-test report.
- A "Self" test is run by the client alone. A "CTA" or "Supported" test needs the CTA, who can suspend an instrument, suspend a CompID, cancel orders, submit trade reports or cancel trades on the client's behalf, and send a private News announcement.
- For every step the client records in the report: CompID, client IP address, test time, the required IDs (Order ID, Client Order ID, Execution ID and so on), a comment, and Pass/Fail. When a step's result differs from the expected result, the client must record the actual result and the IDs needed to identify the step.
- The Volume 202 report has these sheets: Clt Information (client name, software name and release, JSE Customer Test Analyst, self-conformance date, CTA conformance date, scope TRD, INFO, GEN or ALL, and gateways to conform: Native Trading, Native Recovery, FIX Trading, Post Trade, Drop Copy, FIX/FAST Replay and Recovery, MITCH Replay and Recovery); Client Func. Exception (each test step the software is exempted from, with the JSE's comment and whether the exemption was granted); High Lvl Tst (list of tests I1–I13, T1–T24, G1–G2, OT1); Info Conf., Trd Conf., Gen. Conformance and Optional Test Cases (one row per test step with columns Test Case ID, description, Market, Mandatory, Conformance Exemption Agreed with JSE, Self / CTA Test, Requirements, Client Interface User ID (CompID), Client IP Address, Test Time, Client Response to Required Field 1–3, Client Comment, JSE Comment, Test Result Pass / Fail).
- Mandatory testing applies to every function marked Mandatory "Y" that the client's software uses. A step on the Client Func. Exception sheet with the exemption granted is not required. Tests marked Mandatory "N" (for example T1-002, T1-003, the self-match prevention tests) apply when the client's software offers that function.
- Volume 202 numbers two different tests `T3-013`: the iceberg order test and the Native self-match prevention test. Ask which one is meant if an analyst says only "T3-013".
- Who must conform: a host-to-host trading client using its own software must conform Native trading, FIX trading, Post Trade and Drop Copy; a host-to-host information client using its own software must conform the market data services; clients using software from a JSE-accredited provider or a shared infrastructure provider do not need mandatory conformance; software providers must conform everything their software offers.
- The Post Trade Gateway (including Own Trades Book Download) and the Drop Copy Gateway (including Own Order Book Download) are mandatory for trading applications of JSE members, because they are how a member recovers trades and open orders if the JSE fails over to its disaster recovery site.
