Project brief

JSE Data & Digital Academy final case study, Group 6 · Tshephang Tsheoga, Ndivhuwo Makhavhu, Sixolisile Mahlasela · Sponsor: Head of Trading Operations

The problem

Before a client may trade on the JSE or receive production market data, Trading Operations must confirm that the client's systems send and handle messages as the JSE specifications require. The client runs a set of conformance tests under a CompID, the login name of one client connection to the JSE trading gateway, and every message of those tests is recorded. A conformance report then states whether each test passed.

When a report shows less than a 100% pass rate, an analyst checks the recorded messages by hand to find the cause. In some cases the report shows a test as failed although the messages show the client completed it. The analyst then asks the client for more information or a retest, which delays the client's move to production. Few analysts know how each test is configured, so the work depends on those people being available.

What the system does

TaskWhat happens
Answer questionsThe analyst types a question in the chat, such as which messages of a CompID were rejected and why. The agent writes and runs SQL queries on the message data in the browser and answers in plain words.
Check a client's reportThe analyst attaches the client's conformance test report (Excel or PDF). The system finds the messages of each test step and gives the step one result: Pass, Fail, Needs review, Not checkable or Not attempted, with the reason.
Write the reply to the clientThe system writes a report for the client, as Excel or PDF, with a summary and one row per test step with its result and reason.

How the result is measured

  • Time an analyst takes to check one client's conformance report, by hand and with the system.
  • Number of test steps the system gives the same result as the analyst.
  • Number of follow-up requests and retests sent to clients.
  • Number of clients completing conformance, and their pass and fail rates.
