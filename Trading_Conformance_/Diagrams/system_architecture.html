Trading Conformance Agent: system architecture

An analyst types a question about the Vonnegut FIX message exports into a web page. A language model on OpenRouter writes SQL queries, the server runs them against the July–September 2026 data, and the model writes the answer from the query results.

Answering one question

  1. 1The browser sends the whole conversation so far to POST /api/chat. The server keeps no conversation history between questions.
  2. 2server.py checks that the data has finished loading and passes the conversation to agent.chat().
  3. 3agent.py sends OpenRouter the system prompt (conformance background, table names, standard FIX code meanings), the conversation, and the definitions of three tools: list_tables, describe_table and run_sql.
  4. 4The model returns either a tool call, for example run_sql with a SQL query it has written, or the final answer text.
  5. 5agent.py runs the tool call in data_store.py. Anything other than a single SELECT statement is refused.
  6. 6The result goes back to agent.py: at most 200 rows, cut to 30,000 characters. It is added to the conversation and step 3 runs again.
  7. 7When the model returns answer text, agent.py passes it back to the server with the list of tool calls that were made.
  8. 8The page shows the answer, and under it each tool call with its SQL and result, so the analyst can check every number.

Loading the data and settings

  1. AWhen the server starts, data_store.py reads each Excel file with python-calamine, renames columns to lower case with underscores, converts timestamps, prices and quantities, and saves a Parquet copy. This takes several minutes the first time and is skipped for files that have not changed.
  2. BThe Parquet copies are combined into one DuckDB table per FIX message type, all three months together. Each Excel file is assigned to a table by the value in its Message Type column, not by its file name. File and network access are then switched off for the database.
  3. Cconfig.py reads code/.env: the OpenRouter key and default model used by agent.py, the data folder used by data_store.py, and the port used by server.py. The model can also be changed for each question in the page's sidebar.
